# 阶段 4：关键屏低保真（任务卡）

只做阶段 3 提名的 2–3 个关键屏，**灰框 + 真实文案数据**，每屏 ×2 变体。决定布局区域/信息优先级/导航方式；**不决定**颜色字体质感。布局错误在灰框期废弃成本≈0。

输入：`03-屏幕与IA.md` 关键屏名单 + 设计前提。生成 HTML 前按 html-conventions 执行：锁项目画布（宽高都锁）、内容区内部滚动、浮层居中覆盖层、wireframe 灰阶 token（纯灰/无图/图标用文字/真实数据/触控 ≥48px）。

## 产出（`04-wireframes/`）

- `<screen-id>-v1.html` / `-v2.html`：每文件内**多状态帧并排**（一帧一态，帧下灰字标注=设计理由不是内容），**必须覆盖异常态**（空/中断/错误——对照 02 状态机与 03 盘点行）；
- `index.html`：变体对照板——每对变体写明**要决策的问题**（"X 放哪：贴 A 还是固定 B？"式）。

变体要求：差异在**布局结构**（反馈位置/面板形态/组织方式级分叉），不是同布局微调（假变体=gate 不过）。

## 完成标志（L1 gate）

每个关键屏 v1/v2 齐；index.html 带决策问题；全部 HTML 过三查 gate（标签配平/画布锁定/负面文案）；每屏状态帧 ≥2 且含异常态。

## 工具化要点

- 决策类型=gallery：界面按 `*-v1/-v2` 文件对生成变体选择卡，可混搭（如 V1 的反馈位置+V2 的面板形态），拍板记台账（S-x=V?）。品味类：任何模式必停人工。
- 布局模式可回指 03 的模式倾向（超出模式库须声明理由）。
