# 阶段 0 评审判据卡：影响分析（增量变更）

评审对象：`00-impact.md` + `00-impact.json`（revision 工作区）。上游锚点：`00-change-request.md`（新需求）、基线 `03-屏幕与IA.md`、`02-流程草图.md`、`09-spec.md`。先读 `review-conventions.md`。
决策类别：**事实类+范围界定**（影响判定有结构判据；页面/流程对照基线可判）。
注：L1 验 JSON 结构合法性与页面存在性；评审不重复，专注「分析是否如实、不漏不夸」。

## 判据

| # | 判据（离散，三值判定） | 级别 |
|---|---|---|
| R0-1 | 新需求的每一项改动都能落到 pages/flows/navigation/states 中至少一处（读 00-change-request 逐条对照，漏项=命中） | 🔴 |
| R0-2 | 每项修改页的分级正确：content/component/layout/style 与改动描述一致（如"调整卡片布局结构"标 content=命中） | 🔴 |
| R0-3 | 修改/删除页均在基线 03 盘点中，新增页不与基线冲突且挂载点（导航/流程入口）有说明 | 🔴 |
| R0-4 | 导航、流程、共享 token/组件任一受影响时 regression_pages 覆盖关联页面与主流程页（空缺或只列变更页自身=命中） | 🔴 |
| R0-5 | shared_change 如实：需求触及视觉系统/组件族却标 false=命中 | 🔴 |
| R0-6 | states 与修改页匹配：声明的新状态落在被修改/新增的页面上，不凭空挂在未变更页 | 🟡 |
| R0-7 | added 页给了 name 与挂载理由（供阶段 2/3 更新流程与 IA 消费） | 🟡 |
| R0-8 | removed 页说明了入口与流程收口（删页不收口=导航断链） | 🟡 |
| R0-9 | 00-impact.md 与 JSON 一致（人读版不夹带 JSON 之外的新结论） | 🟡 |

## 常见命中示例

- R0-1 命中：`新需求要求"打卡日历支持补签"，pages/flows/states 均未提及`
- R0-2 命中：`"把词本两组列表改为三 Tab 分段"标 content，实为 layout`
- R0-4 命中：`navigation 声明底部导航新增入口，regression_pages 为空`

## 放行

🔴=0 且覆盖完整 → revision 进入 impact_ready，等用户**确认范围**后才启动增量任务（不自动重跑）。
分析夸大（多列无关页面/级别虚高）→ 打回收紧；拿不准的级别保守取高一级不算错，但须给理由。
