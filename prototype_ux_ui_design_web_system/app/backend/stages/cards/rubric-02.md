# 阶段 2 评审判据卡：流程草图

评审对象：`02-流程草图.md`。上游锚点：`01-需求消化.md` 的 job stories 与已拍板前提。先读 `review-conventions.md`。
决策类别：**事实类**（走向对错可判；P2-x 新问题 auto 模式按倾向记录台账，用户可后续推翻）。
注：mermaid 无断链/无孤儿由 L1 脚本验，评审不重复验，只判语义。

## 判据

| # | 判据（离散，三值判定） | 级别 |
|---|---|---|
| R2-1 | 核心任务流 3–5 条，动宾命名（如 `P1-提交报销单`），不是名词命名 | 🔴 |
| R2-2 | 恰好一条主流程标注为"产品脊柱"（后续关键屏从它提名） | 🔴 |
| R2-3 | 每条流程五件套：触发 / 步骤 / 判断 / 异常分支 / 出口（异常分支缺失=命中） | 🔴 |
| R2-4 | 每个核心场景的 job story 被某条流程覆盖（逐条 story 核对归属，无孤儿 story） | 🔴 |
| R2-5 | 变体与支线不独立成流：以参数变体/虚线支线挂载并明确标注 | 🟡 |
| R2-6 | 业务规则有编号（R#）且挂在发生的边上，无悬空规则 | 🔴 |
| R2-7 | 复杂屏内部状态用 subgraph 表达（状态机心脏），且与停留点区分 | 🟡 |
| R2-8 | 尾部两节齐：**流程教给我们的事**（洞察）+ **P2-x 新问题**（每条带倾向） | 🔴 |
| R2-9 | P2-x 与 A-x/B-x 无重复（已问过的不换皮再问） | 🟡 |
| R2-10 | 流程粒度是"用户怎么流动"而非页面长什么样（节点里出现布局/控件描述=命中） | 🟡 |

## 常见命中示例

- R2-3 命中：`P2-完成练习 从'进行中'直达'出口'，无中断/异常分支`
- R2-4 命中：`story"当调音时我想… "没有任何流程包含调音停留点`
- R2-6 命中：`文中写"规则：每日限 3 次"但边上无 R# 挂载`
