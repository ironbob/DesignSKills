# 阶段 1 评审判据卡：需求消化

评审对象：`01-需求消化.md` + `.stage1-questions.json`（工具模式的机器可读问题单；skill 模式问题内嵌在 memo「问题清单」节，此时 R1-10 对 memo 内问题清单判定，不以 JSON 缺失为命中）。先读 `review-conventions.md`（独立性硬约束与 findings 契约）。
决策类别：**答案类**——评审只判 memo 质量，A-x 由用户回答，任何模式不停自动拍板。

## 判据

| # | 判据（离散，三值判定） | 级别 |
|---|---|---|
| R1-1 | 六节齐：一句话重述 / job stories / 设计张力 / 问题清单 / 成功标准 / 台账骨架（标题级核对） | 🔴 |
| R1-2 | 一句话重述是设计视角（帮谁·场景·完成什么），不是功能罗列复述 | 🟡 |
| R1-3 | 每个核心场景 ≥1 条 job story，格式 `当【】时，我想【】，以便【】` 且标人像 | 🔴 |
| R1-4 | 张力 3–6 条，每条是设计判断而非功能诉求 | 🟡 |
| R1-5 | 每个 A-x 注明"为什么阻塞"（答案影响哪个下游决策） | 🔴 |
| R1-6 | 每个 B-x 带默认假设（不清空即生效） | 🔴 |
| R1-7 | 功课声明存在：哪些问题本可自查、查证结果如何 | 🟡 |
| R1-8 | 成功标准 ≤6 条且每条可度量（距离/时长/触控次数/矩阵覆盖等），与功能验收可区分 | 🔴 |
| R1-9 | PRD 未决点全覆盖：出现在问题清单（A/B）中，无静默遗漏 | 🔴 |
| R1-10 | `.stage1-questions.json` 结构：blocking 每题 ≥2 选项、恰好一个 recommend、选项三件套齐（L1 已验结构，此处验语义：选项之间真实互斥、consequence 写的是反面后果而非优点复读） | 🟡 |
| R1-11 | 推荐选项与 memo 张力/成功标准自洽（推荐理由能在文中找到根据） | 🟡 |

## 常见命中示例

- R1-3 命中：`stories 只写了"用户想练习"，无触发情境与收益三段式`
- R1-8 命中：`成功标准"界面美观易用"不可度量`
- R1-10 命中：`A-1 两选项 consequence 均为"体验更好"，无反面后果`

## 放行

🔴=0 且判据覆盖完整 → memo 过审，问题单交用户（答案类必停人工）。
