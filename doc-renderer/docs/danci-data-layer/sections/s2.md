## 背景：iOS 14 时代的 Core Data 撑不住新形态 {#s2}

<p class="lead">离线刷题、多设备同步、SRS 调度加入后，写入卡顿与迁移困难已经不是修补能压住的问题。</p>

数据层搭建于 iOS 14 时代，最初只服务单机词库查询。离线刷题把写入频率抬了一个量级，SRS 调度引入高频复杂查询，多设备同步则要求可靠的本地操作记录——三类新负载全部压在同一套 Core Data 栈上。

写入卡顿直接伤刷题手感，迁移困难则拖慢每一次数据模型演进。在既有约束下评估：继续修补的边际收益递减，整体替换存储框架并引入同步引擎，才能支撑未来两年的功能演进。

| 约束 | 取值 |
|---|---|
| 系统基线 | iOS 16+ 起步 |
| 团队技术栈 | Swift 为主 |
| 架构原则 | 离线优先 |

<Callout type="risk">写入卡顿与迁移困难为团队定性结论（未做卡顿率量化），本方案聚焦替换路径与预研证据，不对现状问题做数字外推。</Callout>
