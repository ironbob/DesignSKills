## 候选对比：官方方案为何落选 {#s4}

<p class="lead">落选不是印象分——SwiftData 三条硬伤、CloudKit 两处不可控、Protobuf 一个成本不等式。</p>

**SwiftData** 与 SwiftUI 亲和度最高，团队评估后放弃：`@Model` 非 Sendable 限制多线程写入，而离线刷题恰是高并发写场景；iCloud 同步行为黑盒，出问题排障无从下手；迁移无法精细控制——与我们要逃离的痛点同构。

**CloudKit** 免运维有吸引力，但同步冲突策略不可控，「服务端时间戳优先」这类业务策略无法注入；且无法支持 Android 端的未来规划——同步协议必须握在自己手里。

**Protobuf** 预研序列化性能占优（包体积减少 38%），但需要维护双端 schema，学习成本高于收益——38% 的体积收益换不来协议层的长期维护负担。
