# 已有 app 改风格 · 审计清单

> 场景 B（大范围优化）的执行手册。产出 = 差距报告 + 目标态演示，用户确认后才开始迁移。

## 审计流程

1. **运行摘要扫描**：先运行 `<skill>/scripts/audit-ui-style.py --project <project> --style <style> --format json`，
   只把紧凑 JSON 摘要放进上下文；命中规则后再读对应规范章节。
2. **并行盘点四组表面**：在工具允许时同时检查全局/Token、组件状态、交互响应式、无障碍；
   不要把无依赖的检查串行执行。
3. **全局 CSS**：先查全局 CSS / 主题变量 / 组件库覆盖层——审计必须从全局层开始，
   只看组件会漏掉被全局规则污染的样式（历史教训：scoped 改不动是被全局 `!important`
   或 `background` 简写遮蔽）。
4. **Token 差距**：现有颜色/字号/圆角/间距/动效逐项对照目标风格 `tokens.md`，
   标记"写死值→应改 token"清单。
5. **反模式扫描**：逐条对照目标风格 `patterns.md` 的反模式清单（条数以各风格包为准），
   每命中一条记录位置。
6. **状态矩阵核查**：抽样控件核对 hover/按压/激活/quiet-active/打开态/禁用/焦点环
   是否齐全且符合单强调色规则（finder=系统蓝 / linear=品牌紫 / things=Things 蓝 /
   geist=黑白单色+黑主按钮 / figma=中性灰+选中蓝）。
7. **交互一致性**：键盘（捕获阶段 LIFO、Esc 链）、焦点环、窗口失活语义、
   降级阈值（窄窗行为）是否达标。
8. **并行生成交付物**：用 `<skill>/scripts/render-custom-preview.py` 生成目标态 mock，同时整理差距报告，
   然后交用户完成视觉确认和独立的实施授权。

## 差距报告模板

```markdown
# <app> → <风格> 迁移差距报告

## 概览
- 命中反模式：N 处（高/中/低风险 x/y/z）
- 缺失 token：… 个写死值需收敛
- 状态矩阵缺口：… 控件缺 hover/焦点环/禁用态

## 分区域明细
| 区域 | 现状 | 目标（规范章节） | 风险 | 工作量 |
| --- | --- | --- | --- | --- |
| 工具栏 | 灰底连续条+竖线 | 胶囊模型（materials §3） | 中 | 0.5d |

## 反模式命中清单
1. `<文件:行>` 渐变按钮（patterns 反模式 #1）…
…

## 建议迁移顺序
Token 落地 → 全局 chrome → 逐组件 → 反模式清零复查
```

## 迁移执行规则

- 一次会话只迁一个区域，迁完自查反模式清单再进下一区域。
- 写死值一律替换为语义 token，不保留"暂时性硬编码"。
- 迁移期间发现规范未覆盖的场景：优先回风格包 patterns 找近义模式；确实缺失则
  在报告中标注"规范缺口"，迁移后回写风格包 references（这是风格包进化的主要来源）。
