# Codex 风格 · 布局与交互模式（v0.x）

> 三栏任务工作区、检查器和 composer 是 `archetype-bound` 或 `source-specific`。目标产品没有同类
> 功能时保留原区域关系，只迁移安静中性层级、阅读排版、克制操作和低对比状态。

## 1. 窗口解剖

```text
┌──────────── 270px ───────────┬──────── 主任务流（阅读宽度受控）────────┬─ 检查器 272px ─┐
│ 品牌 / 新对话 / 搜索          │ 当前任务顶栏                            │ 环境信息        │
│ 项目树 + 对话树                │ 说明、回复、代码、附件                  │ 变量、分支、来源 │
│ 账户（底部固定）               │                                [composer] │ 可关闭浮卡       │
└──────────────────────────────┴─────────────────────────────────────────┴─────────────────┘
```

- 左侧栏是工作空间定位；中列是任务处理；右侧是可选上下文区域，可承载 summary、files、terminal 或 browser，职责不能与主任务流互换。
- 空项目态将问题居中（图标、单句问题、composer），不要放大标题或插画；底部可显示项目、位置与分支状态胶囊。
- 正在处理的任务在主内容顶端以极短耗时行提示；不要用全屏 loading 遮罩。

## 2. 自适应与面板

| 宽度 | 行为 |
| --- | --- |
| ≥ 1280px | 左栏 + 主内容 + 右检查器；检查器可以浮卡式内缩 |
| 980–1279px | 默认隐藏检查器，以右上图标按需打开 overlay |
| 760–979px | 左栏变为 overlay 抽屉；主内容留 24px 水平边距 |
| < 760px | 只保留任务顶栏与主列；composer 贴底并保留安全区 |

菜单与检查器打开时必须钳制在视口内；不挤压任务正文，不让固定 composer 被遮挡。

## 3. 键盘与焦点

- 焦点环只在键盘导航出现；图标按钮必须有 `aria-label` 或 `title`。
- `Esc` 按 LIFO 关闭：项目菜单 → 检查器 overlay → composer 附件/子菜单；不应直接丢失任务草稿。
- 项目切换菜单用 ↑↓ 移动、Enter 选择、输入即过滤；不做 hover 才能看见的关键操作。
- 只有正文、代码、输入框和可复制路径允许 `user-select: text`；导航行默认避免文本选择。

## 4. 主题

- 根节点采用 `data-theme="light|dark"`；组件只能消费 token。
- 暗色保持安静的暖中性层级，避免纯黑画布与高饱和蓝色大面积出现。
- 亮色是截图证据的主要风格，应作为默认主题。

## 5. 截图证据边界

- 可直接采用：三栏工作区、居中内容宽度、低对比中性选中、圆角输入台、右检查器、蓝色未读点、深色提交按钮、项目菜单结构。
- 需根据产品验证：系统窗口控制、终端面板、语音入口、变更统计、模型名、具体快捷键与暗色主题数值。
