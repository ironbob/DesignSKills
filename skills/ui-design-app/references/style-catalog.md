# 风格目录（style catalog）

> 推荐阶段的唯一读取物。每条目 = 推荐决策需要的全部元信息。

## 推荐决策规则

1. 先确认三个信号：**平台**（macOS / 跨平台 / Web）、**应用类型**（效率工具 / 内容浏览 / 管理后台 / 创作工具）、**气质偏好**（原生融入 vs 独立品牌感 / 宽松 vs 紧凑 / 鼠标 vs 键盘）。
2. 按下表匹配；命中多个时取 2-3 个候选给用户选，并在演示页上肉眼对比。
3. 用户描述含明确风格名（"像 Finder""像 Linear"）→ 直通，不再推荐。

## 风格矩阵

### finder —— macOS 原生 Finder 观感

| 维度 | 内容 |
| --- | --- |
| 定位 | 让 app 看起来是 macOS 系统一员：vibrancy 半透明材质、系统蓝、NSMenu 右键菜单、窗口失活降级 |
| 适用 | macOS 优先的桌面工具（文件/设备/媒体/编辑器类）；追求"原生感、无 Web 味"的任何桌面 app |
| 关键词 | 原生、材质、毛玻璃、系统蓝、Finder、宽松、鼠标优先 |
| 不适用 | 品牌驱动的产品站/SaaS 后台；需要强品牌色的 app（主色锁定系统蓝）；键盘重度效率流（密度偏松） |
| 与 linear 的核心差异 | 有材质模糊 vs 纯实色；系统蓝 vs 品牌紫；28-36px 控件/13px 行 vs 26-28px 控件/更紧；NSMenu vs 自绘菜单 |
| 成熟度 | v1.0（来自一个完整 Electron 应用的全量实战与三轮审计） |
| 演示 | `assets/styles/finder/demo.html` |

### linear —— 现代 SaaS 效率风

| 维度 | 内容 |
| --- | --- |
| 定位 | Linear/Notion 一脉的效率工具风：中性灰阶 + 单一强调色、紧凑列表、键控交互、快速微动效 |
| 适用 | Web app / SaaS 后台 / 项目与任务工具 / 开发者工具；键盘优先的高频操作流 |
| 关键词 | 紧凑、灰阶、单强调色、键盘优先、命令面板、⌘K、效率 |
| 不适用 | 追求 OS 原生融入的桌面 app（无材质、无 NSMenu）；休闲/内容消费类（密度过高显严肃） |
| 与 finder 的核心差异 | 见 finder 行（互为反面） |
| 成熟度 | v0.x（可用级：tokens/components 完整，patterns 简版，未经实战打磨） |
| 演示 | `assets/styles/linear/demo.html` |

### things —— Things 3 清爽产品风（macOS）

| 维度 | 内容 |
| --- | --- |
| 定位 | Apple Design Award 级的 macOS 清爽产品风：白净实色 + Things 蓝、大标题、大留白、圆形控件、宽松行距——"有产品个性"而非"系统一员" |
| 适用 | macOS 优先的消费者工具（任务/笔记/日历/阅读/习惯类）；追求"干净愉悦"、以亮色为人设默认的 app |
| 关键词 | 白净、大留白、宽松、圆形复选框、区域色点、大标题、Things 蓝、鼠标优先、柔和动效 |
| 不适用 | 数据密集后台（密度太松）；键盘重度效率流（快捷键默认隐藏）；以深色为人设的产品 |
| 与 finder 的核心差异 | 同为 macOS 观感：独立品牌 vs 系统一员——实色无 vibrancy、Things 蓝 vs 系统蓝、40-44 行 vs 30-36 行、圆形控件+完成划线动效 vs NSMenu 方正控件 |
| 成熟度 | v0.x（凭真实 app 使用印象近似提炼，未经逐像素核对） |
| 演示 | `assets/styles/things/demo.html` |

### geist —— Vercel/Geist 开发者仪表盘风

| 维度 | 内容 |
| --- | --- |
| 定位 | Vercel dashboard 一脉：纯黑白灰单色系 + **黑色主按钮** + 真黑（#000）暗色 + 等宽字体点缀 + 状态 pill 允许淡彩底 |
| 适用 | Web 仪表盘 / 管理后台 / 开发者工具 / infra·部署·监控·分析类数据密集 SaaS |
| 关键词 | 单色系、黑主按钮、真黑、等宽点缀、状态 pill、键值设置行、表格、⌘K |
| 不适用 | 需要品牌彩色表达的产品（主色即黑）；内容消费/创作工具；macOS 原生融入需求 |
| 与 linear 的核心差异 | 同为 Web 效率风：黑主按钮 vs 品牌紫主按钮；纯黑白灰 vs 灰阶+紫强调；状态 pill 淡彩底 vs 禁彩底；36-40 行 vs 28-32 行；等宽点缀 vs kbd chip 处处可见 |
| 成熟度 | v0.x（凭真实 app 使用印象近似提炼，未经逐像素核对） |
| 演示 | `assets/styles/geist/demo.html` |

### figma —— Figma 创作工具风

| 维度 | 内容 |
| --- | --- |
| 定位 | Figma UI3 一脉的专业创作工具 chrome：中灰画板 + 三块白色圆角浮动面板（顶工具条/左图层/右属性）、微型控件、选中蓝画布语义、单键工具切换 |
| 适用 | 创作/编辑工具（设计器、编辑器、建模、白板、画布类）；"画布 + 面板"结构的任何专业工具 |
| 关键词 | 浮动面板、灰画板、微型控件、图层树、属性面板、单键工具（V/A/R/T）、最紧凑 |
| 不适用 | 列表/详情型效率工具（无画布语义）；消费者休闲产品（密度过高）；文档阅读类 |
| 与 linear 的核心差异 | 画布+浮板 vs 三栏贴边；12px 字号/24-28 控件 vs 13px/26-28；选中蓝作用于画布对象+手柄 vs 列表弱紫底；键盘是模式切换 vs 命令面板 |
| 成熟度 | v0.x（凭真实 app 使用印象近似提炼，未经逐像素核对） |
| 演示 | `assets/styles/figma/demo.html` |

## 候选卡片呈现要求

用结构化用户输入或简短文字给候选时，每张卡片必须含：风格名 + 一句话定位 + 与其他候选的
一句差异 + demo 路径提示（"已为你打开演示页"）。**不要**只给风格名让用户盲选。

## 如何新增风格

1. 建 `references/styles/<id>/` 四件套与 `assets/styles/<id>/` 三件（契约见 SKILL.md）。
2. demo.html 必须离线自包含；CSS 数值与 references 完全一致（demo 是规范的活样张）。
3. 在本文件矩阵追加条目，标注成熟度 v0.x。
4. 首选从真实 app 提炼（像 finder 那样），凭印象写的风格长期停留在 v0.x。
