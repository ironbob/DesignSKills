# 风格证据标准

> 风格包不是品牌规范的替代品。它把可核验事实、设计归纳和目标产品适配分开，避免把印象、旧版本或业务布局伪装成“精确复刻”。

## 1. 三类结论

- `observed`：官方产品、官方截图、官方设计系统或当前受控样本直接支持的事实。必须能回指 `evidence.md` 的来源 ID。
- `derived`：由多个 observed 样本归纳出的规律，或从截图估算的尺寸/节奏。必须声明估算范围，不能写成官方精确值。
- `adapted`：为了目标功能、平台、无障碍、性能或响应式而主动调整的规则。它可以偏离来源，但必须解释原因。

数值只有在官方 Token、可检查 DOM/CSS 或同版本测量样本支持时才可标为 observed。仅凭截图估算的 px、颜色和动效时长一律是 derived。

## 2. 证据等级

| 等级 | 最低条件 | 可用于 |
| --- | --- | --- |
| A | 同版本官方规范/Token + 多个官方视觉样本 + 关键状态样本 + 明确版本 | 高置信实现；仍不代表商标或源码授权 |
| B | 至少两个同源官方页面，覆盖骨架、视觉语言和主要交互；数值多为 derived | 高质量风格迁移与设计评审 |
| C | 官方资料只覆盖功能或少量截图，视觉状态/数值缺口明显 | 方向探索；不得宣称精密复刻 |

`+/-` 只作人工摘要，校验器按 A/B/C 主等级处理。成熟度与证据等级不同：成熟度描述本包工程完整度，证据等级描述来源可信度。

## 3. 每包必备元数据

`references/styles/<id>/evidence.md` 必须包含：

- `source-product`：来源产品名。
- `source-version`：明确版本、代际或日期截面，禁止只写“最新版”。
- `platforms`：采样平台。
- `collected-at`：ISO 日期。
- `evidence-grade`：A/B/C，可带 `+/-`。
- `representation`：当前 assets 实际代表的版本或配置。

还必须有：官方来源、observed、derived、adapted、证据缺口与禁止断言、刷新条件。

## 4. 视觉样本最小覆盖

高质量迁移至少需要判断以下覆盖，不适用项写 N/A：

1. 宽窗默认态与核心骨架。
2. 选中、hover/pressed、focus-visible、disabled。
3. 菜单、弹窗或命令面板等至少一种浮层。
4. 空、加载、错误或长内容中的至少两类。
5. 窄窗/面板折叠，或明确说明该来源没有响应式样本。
6. 亮暗主题；单主题产品写 N/A，不自行补造。

官方营销截图能证明构图和表面关系，通常不能证明键盘、焦点、禁用、错误态或精确数值。

## 5. 可靠性门

- 版本不一致时，旧样本只能放进历史差异，不能支撑当前 invariant。
- 来源产品允许主题定制时，不把某一截图的强调色写成唯一官方颜色。
- 官方设计系统覆盖多种颜色/组件时，不能把一个产品配置宣称为完整设计系统。
- 来源布局属于业务原型时，只能是 `archetype-bound`；不兼容即 N/A。
- 没有同版本视觉证据时，风格身份可作为 derived 方向，但证据等级不得高于 C。
- 每次来源发生大版本、平台视觉系统变化或官方页面撤回时，重新采样并运行校验。
