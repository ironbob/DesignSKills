# 阶段 6：排版系统 · 底座组件档（任务卡）

## 目的

固化「这篇文档用什么组件、什么档位」。渲染底座（doc-renderer）已内建主题与组件库（KpiRow / FigureChart / Callout / CompareMatrix + chartTheme 统一图表主题层），本阶段做**覆盖核对与定向扩展**，不再从零造排版系统——这是底座存在的意义：一处定义、篇篇一致。

## 输入

阶段 5 拍板的档位 + `04` 形式清单（组件需求来源）+ 底座现有组件集。

## 产出

1. **组件覆盖核对**：04 清单每个内容块的类型 → 底座组件映射表；缺组件则**定向扩展**（新组件放底座 `theme/components/`，带 props 约定与降级形态，一次开发全库复用）；
2. **图表主题确认**：`chartTheme.ts` 的 token（accent/grey/grid/字号）与档位一致；04 清单里的图型在数据层有对应构造器（如 `pairBars`），缺则补；
3. **档位应用**：选定档位设为该文档生效档（或在 per-doc 覆盖变量）；
4. **组件样张**：底座样张页（`docs/_components/` 或临时页）过一遍将用到的全部组件 × 真实内容。

## 完成标志

04 形式清单所需组件/图型构造器全部就位（映射表无空洞）；样张构建通过且组件无 console 错误；用户确认。图表观感不再逐图手调——`withTheme()` 注入是纪律，option 只写数据与意图。

## 人工决策点

确认组件映射与档位（新组件的 props 设计若涉及表达力取舍，在此拍）。

## 坑

- 绕过 chartTheme 手配 option（观感漂移的老路）——option 里出现颜色/字号裸值即违例；
- 为单篇文档在内容目录里写一次性组件（组件进底座，内容目录只放数据）；
- 扩展组件不做降级形态（无 JS/打印时的呈现）。

## 工具化要点

- 组件库即未来网页工具的物料层；映射表 = 物料清单。
- gate：组件完备性自检（04 vs 底座组件集）+ 样张构建 0 错误。
