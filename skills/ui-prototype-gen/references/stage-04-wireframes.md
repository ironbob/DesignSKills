# 阶段 4：关键屏低保真（任务卡）

## 目的

只做阶段 3 提名的 2–3 个关键屏，**灰框 + 真实文案数据**，每屏 ×2 变体。决定的是布局区域/信息优先级/导航方式；**不决定**颜色字体质感。布局错误在灰框期废弃成本≈0。

## 输入

`03-屏幕与IA.md` 关键屏名单 + 设计前提。生成 HTML 前必读 `html-conventions.md`。

## 产出与模板（`04-wireframes/`）

- `<screen-id>-v1.html` / `-v2.html`：每文件内**多状态帧并排**（固定画布 390×844，一帧一态，帧下带灰字标注=设计理由不是内容）；
- `index.html`：变体对照板——每对变体写明**要决策的问题**（"X 放哪：贴 A 还是固定 B？"）。

变体设计要求：

1. **变体差异在结构不在细节**：反馈位置（贴焦点 vs 固定仪表）、面板形态（中央 vs 底部起板）、组织方式（筛选 vs 分组）这类布局级分叉；
2. 状态帧覆盖该屏的模式×状态（含异常态：空/中断/错误——异常态画错是后期 🔴 的最大来源）；
3. 全部 wireframe token（纯灰、无图、图标用文字、**真实数据从灰框起就有**）；
4. 触控目标 ≥48px 画够——密度问题灰框期就现形，不许留到高保真爆。

## 完成标志

`check_artifacts.py 04-wireframes/` 三 gate 全绿；每个待决策问题有成对的两个答案。

## 人工决策点

**每对变体挑方向**（可混搭，如 V1 的反馈位置+V2 的面板形态）；拍板记台账（阶段 4 拍板：S-x=V?）。

## 坑（实战教训）

- 灰框用 lorem = 初级味，真实文案是信息设计的一部分；
- 画布不固定 → 状态帧高度不一、浮层错位、密度问题被掩盖——**必须锁画布**；
- 变体做成"同一布局微调两版"= 假变体，浪费一轮评审。

## 工具化要点（网页工具映射）

- AI 任务：每变体一次有界调用（输入=屏盘点行+约定，输出=单文件 HTML）。
- 界面：变体并排预览（iframe 沙箱）+ 单选/混搭选择器；状态帧缩略图导航。
- gate：`check_artifacts.py` 为任务完成条件（生成→gate→不过自动打回，≤2 次后转人工）。
- 台账：变体选择 = 决策记录。
