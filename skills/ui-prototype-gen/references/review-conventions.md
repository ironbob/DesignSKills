# 评审公约（L2 AI 评审 · 全阶段共用）

生成与评审分离（Generator–Critic）。本公约 + 各阶段判据卡（`rubric-0N.md`）是评审器的全部指令来源；评审器**不读生成任务卡、不读生成过程的推理**——fresh context，防错误相关。

## 评审独立性（硬约束）

1. **只读产物，不改产物**：评审会话禁止 Write/Edit 任何阶段产物；唯一输出是 findings（沿用"crit 只出 findings，修复独立做"）。
2. **判据离散**：每条判据只有三值——`命中`（违规）/`未命中`（合规）/`不适用`（写明理由）。**禁止打分**（无 1-10、无权重求和）。
3. **证据强制**：每条命中必须给"文件 + 位置 + 原文引用"，不可复核的印象不算 finding。
4. **verdict 不归评审器**：`🔴=0 → 通过` 由编排引擎数出来，评审器只陈述事实、无自由裁量权（防打分通胀与心软放行）。

## findings 数据契约（机器可读，引擎消费）

```json
{
  "stage": 1,
  "findings": [
    {
      "id": "F1-1",
      "criterion": "R1-3",
      "severity": "red",
      "evidence": "01-需求消化.md §问题清单 A-2：未注明'为什么阻塞'（原文：'…要不要区分老师/学生？'）",
      "suggestion": "补阻塞理由：该答案决定 IA 是否分角色壳"
    }
  ],
  "covered": ["R1-1", "R1-2", "R1-4"],
  "not_applicable": [{ "criterion": "R1-9", "reason": "无上一轮产物" }]
}
```

- `severity`：`red`（🔴 必修，放行阻断）/ `yellow`（🟡 须记录，可带病通过）。
- `covered` + `not_applicable` 合计必须等于判据全集——**沉默即违规**（判据没过完 = 评审不完整，引擎视为不可信，等同 red）。

## 放行语义（编排引擎执行）

```
L1 确定性 gate（脚本）全绿
  AND L2 评审 🔴 = 0 且判据覆盖完整
  AND 累计重试 ≤ 2（生成打回与评审打回共享预算，防讨好评审器）
→ 通过：auto 模式下事实类阶段自动拍板进下一阶段；step 模式停人工拍板
→ 任一不满足 → 打回重做；重试用尽 → 转人工（失败无损）
```

## 决策类别（auto 模式的停走依据）

| 类别 | 阶段 | auto 模式行为 |
|---|---|---|
| 答案类（只有用户知道） | 1 阻塞问题 | **必停人工** |
| 品味类（用户偏好，非对错） | 4 挑变体 / 5 挑方向 | **必停人工**（评审可先给对比分析降低决策成本） |
| 豁免类（审计批准） | 8 crit 处置（豁免是否成立） | **必停人工** |
| 事实类（可离散判定） | 2 / 3 / 6 / 7 / 9 | gate+评审放行即自动推进 |

## 模式感知（deliberate/rapid，引擎注入）

- 模式由编排引擎**显式注入**生成 prompt 与评审上下文（rapid 附「模式上下文」块）；评审器不得自行判断或猜测模式。
- rapid 下判据卡的"候选数量"类条目（rubric-04 的 R4-1/R4-2、rubric-05 的 R5-1/R5-8）按 not_applicable+理由处理，不判红；替代验证=单套方案有清晰依据、台账 rapid_default 决策可追溯；该阶段**其余判据照常三值判定**（质量底线不随模式移动）。
- deliberate 下所有判据完全不变；两档共用同一判据卡（模式只改变个别条目的适用性，不另立卡片）。

## 校准（防评审器漂移）

- 金标准回测：已知良好产物（本地自备的人审通过全套；工具经 `--gold` / `WB_GOLD_DIR` 指定目录）跑评审，🔴 必须为 0（假阳性监控）。
- 通过率监控：连续放行率逼近 100% = 评审器变软的信号，回测校准。
- 评审判据与生成指令同源演化：判据卡引用阶段任务卡的"完成标志"，但**永远单独成卡**。
