# Skill Doctor

准确优先地审查或优化一个指定 skill。按词典序判断，不做加权：

```
功能准确可用度 > context 占用 > 速度 > token 用量
```

低优先级收益不能抵消高优先级退化；更短不等于更好。

## 启动与模式

开始前确认用户明确指定了一个可读取且包含 `SKILL.md` 的目录。目标缺失、不唯一或不是 skill 时，说明原因并停止，不猜测或批量扫描。

根据用户意图选择模式：

- **审查模式**：用户只要求评估、评分、诊断或检查。保持只读，输出评分、发现和风险；不生成修改方案，不要求确认。
- **优化模式**：用户要求修改、优化、精简或重写。先只读审查，再提交完整方案；即使用户要求“直接优化”，也必须获得一次性确认后才能写入。
- 意图不明确时默认使用审查模式。

将目标目录视为唯一可写范围。仓库和目标 skill 的指令优先；目录外依赖只报告风险，不修改。

## 工作流

### 1. 建立基线

先清点目标目录的全部内容和大小。完整读取 `SKILL.md`，并读取会影响行为或输出的直接引用；大型条件资料仅在相关分支需要时加载。对二进制或不可解析内容记录类型和用途，不为节省 context 而盲目加载。

提取：

- 触发条件、目标用户和主结果；
- 主工作流、硬性规则、确认点、输出物和失败边界；
- 目录内外直接依赖及其可达性；
- 已声明的验证、检查和示例；
- 重复内容、无条件大型加载、重复调用或无价值步骤等成本迹象。

区分事实、推断和未知。若需要判断当前可用性，区分“源码有效”与“已安装、已发现或已重新加载”，不要混为一个结论。

### 2. 评分并诊断

在改动建议之前输出基线评分。四个维度独立取 `0–5` 分，`5` 为最佳；不得计算总分、平均分或加权分。

| 分数 | 含义 |
|---:|---|
| 5 | 直接、充分的证据表明满足目标，且没有已知实质缺陷 |
| 4 | 整体可靠，仅有明确、轻微的缺口 |
| 3 | 可用，但有实质缺口或证据不完整 |
| 2 | 有重大缺陷或高风险，通常应先修复 |
| 1 | 基本不能满足目标 |
| 0 | 已知无效、冲突或不可用 |

| 维度 | 评分依据 |
|---|---|
| 功能准确可用度 | 触发精度、目标和流程完整性、约束与异常、引用一致性、验证证据 |
| context 占用 | 核心指令大小、无条件加载、重复说明、按需路由和资料分层 |
| 速度 | 必要读取、搜索、调用、确认往返和验证步骤的数量与重复性 |
| token 用量 | 指令和输出冗余、重复模板及可安全压缩空间；不得以准确性换短小 |

每项使用：`得分 / 观察证据 / 扣分原因或未知项 / 风险`。证据不足时写 `未测` 并说明缺什么，不把“未测”当作 0 分。

按既定优先级列出主要短板。先处理错误触发、流程缺口、冲突、失效引用、安全风险和验证缺失，再判断 context、速度和 token；不适用的维度明确说明。

### 3. 按模式输出

**审查模式**到此输出评分、主要发现、验证证据和残余风险，然后结束。除非用户随后要求优化，否则不提出完整改动方案。

**优化模式**在写入前给出一套可审核方案。每项包含：

- 问题及文件证据；
- 拟议改动和明确不变项；
- 对准确可用度、context、速度、token 的依次影响及未知项；
- 验证依据、受限证据和潜在风险；
- “建议应用”或“不建议应用”及理由。

同时列出受保护语义、目录外依赖风险和无安全改动建议（若适用）。只在存在真实取舍时给替代方案。要求用户一次性确认、拒绝或修订整套方案；确认前不得写入。

### 4. 应用已确认方案

只修改方案明确列出的目标目录内内容，并保持每项改动可追溯。若发现方案依赖错误、范围扩大或可能损害更高优先级，停止该项并报告，不临时扩大授权。

### 5. 验证并报告

先运行目标 skill 声明的安全、无外部副作用检查，再检查 YAML frontmatter、目录内直接引用、确认点、关键约束和改动后的语义一致性。

对行为变化增加最小验证：

- 修改触发描述时，使用至少一个正向和一个负向提示检查边界；
- 修改工作流时，干运行一个正常路径和一个相关失败或确认边界；
- 无法使用宿主、验证器或新会话验证真实触发时，明确标记“验证受限”。

未经另行授权，不运行会写入外部系统、删除数据或产生实质副作用的检查，也不虚构通过结果。

优化模式的最终报告依次给出：

1. `已验证`、`验证失败` 或 `验证受限`；
2. 应用前后四维评分及变化证据；
3. 已应用改动及对应方案项；
4. 可量化或明确标为定性的成本对比；
5. 验证证据、失败项和残余风险；
6. 未改动内容和原因。

只有结构与相关行为证据都充分时使用“已验证”。发现回归、失效引用或冲突时使用“验证失败”；缺少关键行为证据时使用“验证受限”。

## 质量门槛

- 模式与用户意图一致；优化模式确认前无写入；
- 目标仍为一个目录，且未修改目录外内容；
- 四维均有证据或标为“未测”，且没有汇总分掩盖优先级；
- 低优先级优化没有降低更高优先级；
- 关键意图、触发条件、约束、异常和直接引用仍一致；
- 验证结论不超过实际证据；输出只保留决策和理解所需内容。
