# 范围、扩围与分析置信度

## 候选范围

初始范围由以下内容组成：

- 机制对象和入口提示
- 主机制类型；必要时补充次类型
- 候选覆盖文件
- 一句话职责
- 本次可用工具和证据带来的分析置信度

候选文件不是最终完整集合。不要为了确认范围而预先假装已经追完调用链。

## Lite

直接从候选范围开始追踪。只有同时满足以下条件才询问用户：

1. 存在两个或更多实质不同的机制解释；
2. 无法从仓库上下文消除歧义；
3. 选错会明显改变分析对象或输出。

追踪中补充同一目录、同一语言、同一职责下的辅助文件，不需要暂停。

## Full

开始深挖前确认候选范围，并把确认信息写入 Full JSON 的 `scope_confirmations`。追踪中出现以下任一情况属于实质扩围：

- 新根目录或新子系统
- 新语言或新运行时边界
- 新入口
- 不同的最终效果或副作用
- 原职责描述需要实质改写

实质扩围时更新范围、再次确认并追加一条 `trigger=material-expansion` 记录。仅补充同目录辅助文件时直接继续，在报告中记录最终覆盖集合。

## 置信度由证据决定

不要按编程语言预设 high/medium/low。对每种语言记录：

```json
{
  "language": "TypeScript",
  "confidence": "high",
  "basis": "读取了类型定义、全部调用点并运行了示例测试",
  "tools": ["text search", "type checker", "test"]
}
```

判断参考：

- `high`：入口、实现、调用边和最终效果均有直接证据，并有编译、测试或运行验证。
- `medium`：主要链路有直接证据，但部分动态调用、生成代码、外部依赖或运行行为未验证。
- `low`：主要依赖文件名、文本搜索、注释或不完整片段，关键调用边未证实。

同一种语言在不同仓库中的置信度可以不同。
