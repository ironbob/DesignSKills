# 代码读取取证协议：沿链路追踪 + 数值操作识别

> 配合 `tech-mechanism-analysis` 的 Checklist 第 3 步使用。在用户确认的边界内，**沿链路模板分段追踪**机制怎么从起点跑到最终效果，取证五类事实，并**识别其中的数值计算环节**（为第 5 步工作举例铺垫）。多语言、防臆造。

## 一、追踪策略：沿链路模板走，不读入口就停

按确认的 `chain_template` 逐段追，每段回答：

- 数据 / 控制**从哪进来**、**在本段怎么变**、**交到下一段时是什么形态**。
- 跨段衔接处尤其要看：上段写出的格式 / 接口，下段读取时**假设**了什么——这是跨段缺陷的高发区。

**追到底**：从产生追到生效，不要读了 `addKeyframe()` 就停。跨多文件时，用调用关系（LSP incomingCalls/references 或 rg）把链路串起来。

## 二、五类事实（每段取证）

1. **数据结构 / 状态**：存什么、字段含义、单位、精度。
2. **调用 / 依赖边**：谁调谁、调用时机。
3. **算法 / 变换**：本段对数据做了什么运算（**数值段重点**）。
4. **时序 / 触发**：什么时候发生、有无并发 / 周期。
5. **边界 / 兜底**：空 / 越界 / 异常怎么处理。

每条事实挂 `file:line`；推断标 `⚠ 未确认` + 登记 gaps。

## 三、数值操作识别（为第 5 步铺垫）

对每段判：**是否含数值计算**？是则该段 `numerical=true`，第 5 步必须给工作举例。识别口径：

- ✅ 数值操作：插值 / 缓动 / 平滑（EMA / 低通 / 滤波）/ 变换（矩阵 / 色彩空间）/ 量化 / 压缩 / 聚合 / 累加 / 归一化 / 哈希分布计算。
- ❓ 边界：纯索引 / 下标计算——若影响行为（如取模环绕、桶定位）算数值；若只是 `arr[i]` 取值不算。
- ❌ 非数值：纯控制流、状态切换、存储读写无运算。

把识别到的数值操作记下：**操作名 + 代码位置 + 涉及的输入输出**，交给第 5 步做工作举例。

## 四、多语言取证：LSP/rg 双轨

- **先检测 LSP**（本仓库 `analysis-protocol` 通用做法）：有则用 `references` / `incomingCalls` / `implementations` 取调用边与跨段衔接；精度高。
- **不可用**：在对话里给安装建议并等用户回复；否则 **rg 文本搜索降级**，并在段内 / 报告标注「rg 降级，精度受限」。
- 各语言精度按 `scope-and-boundary.md §三` 标注，低精度语言结论保守。

## 五、token 聚焦（对抗大机制噪音）

机制可能跨很多文件，全读会爆 token + 淹没关键链路：

- **沿链路裁剪**：只追与该机制相关的调用链 / 数据路径，不读无关代码。
- **热点优先**：先读链路模板各段的核心文件（入口 + 存储 + 处理 + 生效），再按需补细节。
- **分段取证**：一段读透再下一段，避免一次性铺开。

## 六、防臆造三原则

1. 不照念函数名 / 注释当理解（`interpolate()` ≠ 懂了插值）。
2. 数值操作的公式 / 边界处理要追到代码行，不能凭名字猜。
3. 找不到依据标 `⚠ 未确认` + 缺口，绝不混进正文当事实。
