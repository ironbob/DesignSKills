# 双轴设计债审计（模块 C）

> 配合 `tech-mechanism-analysis` 的 Checklist 第 6 步使用。本 skill 的「缺陷」**不是正确性 bug**，是**设计债 / 可演进性风险**——「因设计问题，某些需求会很难实现 / 维护 / 扩展」。从**架构轴**和**逻辑轴**两章找，每条带四要素例子。**不打分级、不下 go/no-go、不找 bug**。

## 一、核心心法：先想「未来要做什么会卡住」

不要问「这里有没有 bug」，而问：**「如果将来要加 X 需求 / 改 Y 场景，当前设计会不会让它很难？」** 设计债 = 当前设计选择在某个未来需求下暴露出的扩展 / 维护 / 实现成本。每条都落到一个**具体的会变难的需求**。

## 二、两轴（两章，内容不重叠）

### 架构轴（DEBT-ARCH-NN）：结构性设计问题

看：分层 / 职责边界 / 耦合 / 依赖方向 / 不恰当暴露。

- 数据结构和谁耦合？改动会不会牵连多处？
- 处理逻辑是否泄漏到不该知道的层？
- 存储格式是否被多处直接依赖，难以演进？

### 逻辑轴（DEBT-LOGIC-NN）：算法 / 数据 / 状态设计问题

看：算法选择 / 数据结构 / 状态机 / 数据流假设。

- 算法 / 数据结构是否假设过窄（只支持单轨道 / 线性 / 等间隔）？
- 状态机是否缺状态、转移不可表达某些需求？
- 数值处理的假设（精度 / 范围 / 单位）是否限制了未来场景？

> 两轴都从全链路分段里长出来：每条 defect 指向一个 `stage_id`。无该轴问题时显式声明「本机制未识别到架构 / 逻辑轴设计债」，不硬凑。

## 三、四要素（每条 defect 必填，缺一不可）

| 要素 | 写什么 | 反例 |
|------|--------|------|
| `hard_requirement` | **会变难的具体需求**（可描述的未来场景） | ❌「扩展性差」✅「支持多轨道关键帧交错 + 冲突仲裁」 |
| `why_hard` | **当前设计哪里让它难**（指到具体段 / 结构） | ❌「设计不好」✅「关键帧存成单条时间线列表，无轨道维度，读取段与冲突处理都需重写」 |
| `evolution_direction` | **演进 / 松绑方向**（真要做，设计怎么改） | 「引入 track 维度 + 按 (track,time) 索引；冲突走优先级仲裁层」 |
| `cost_impact` | **代价 / 影响评估**（改动面 / 涉及哪些段 / 风险） | 「涉及 produce/flow/process 三段；存储格式迁移；中等风险」 |

> **演进只指方向，不到完整重构方案 / 迁移步骤**（越界）。**不打 severity 分级**（用户明确不要）。

## 四、跨段衔接缺陷专项（高价值，单列）

全链路分析最容易漏、最值钱的发现：段与段**衔接处**的隐含约定脆弱。`cross_stage=true` 单列。常见：

- **数据格式假设不一致**：存储段写格式 X，读取段假设格式 Y（如存弧度、读度）。
- **接口契约脆弱**：上游传的对象字段下游强依赖，缺字段静默错。
- **时序耦合**：生效段假设处理段已完成，无同步保证。
- **隐含约定未文档化**：单位 / 精度 / 范围约定只在脑子里。

每条同样四要素 + 指向涉及的 stage（`stage_id` 取其中一段，`why_hard` 说明跨段）。

## 五、与邻居划界（防越界）

| 本 skill 设计债 | 别处的 |
|-----------------|--------|
| 机制级、从全链路分段长出、带「会变难的需求」例子 | `arch-quality-eval`：模块级坏味道清单 + go/no-go + 分级 |
| 让需求变难的设计选择 | 正确性 bug（输入 X→错误 Y）、崩溃复现——本 skill **不找** |
| 演进方向（指路） | 完整重构方案 / 迁移——本 skill **不给** |

## 六、自检

- 每条四要素非空、需求具体可描述？
- 有没有混入 bug / 崩溃 / 「可能算错」？有就改写成设计债或删。
- 有没有偷偷打 severity？json 不得有 severity 字段。
- 架构 / 逻辑两轴都过了（无则显式声明）？跨段衔接缺陷单列了？
- 每条挂证据 `file:line` + 指向 stage？

## 七、反模式

- 把「这里可能崩 / 算错」当缺陷 → 那是 bug，不是设计债。
- 缺陷只有「扩展性差 / 不够灵活」空话 → 必须落到具体会变难的需求。
- 打 critical/major/minor → 不分级。
- 给完整重构方案 → 只给演进方向。
- 跨段衔接缺陷没单列 → 漏掉高价值区。
