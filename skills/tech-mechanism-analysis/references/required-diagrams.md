# 三张必检图

Lite 和 Full 都必须在详细全链路正文之前给出以下三图。三图不能互相替代，也不能用一张相同内容的图重复命名。

## 业务流程图

回答“从触发到用户/调用方得到结果，经历哪些可观察步骤”。

- 至少 2 个步骤节点和 1 条有向边。
- 节点覆盖触发、关键处理和结果；边说明条件、数据或结果。
- 只画与目标机制直接相关、能由代码或用户输入证明的流程，不反推整个产品业务。
- 每个节点和边都回链源码。

## 时序图

回答“哪些参与者以什么顺序调用、等待、回调或传递消息”。

- 至少 2 个参与者和 1 条消息。
- 参与者优先使用真实类、模块、协程、队列、外部服务或调用方。
- 消息按真实时间顺序排列；异步、循环、取消和异常分支按证据表达。
- 每个参与者和消息都回链源码。

## 架构角色图

回答“哪个类/模块/服务具体负责什么，以及它依赖谁”。

- 至少 2 个角色节点和 1 条依赖/调用/数据边。
- 每个节点必须给 `role`，用动作句说明职责，例如“保存有序关键帧并按时间采样”，不能只重复类名。
- `entity_type` 为 `class` / `module` / `service` / `function` / `data-store` / `external`。
- 每个角色和关系都回链源码。

## 表达与回退

默认使用 Markdown 内嵌 Mermaid：

- 业务流程图：`flowchart LR`
- 时序图：`sequenceDiagram`
- 架构角色图：`flowchart TB`

如果交付环境不支持 Mermaid，可使用 Graphviz、PlantUML、Structurizr 等专业工具导出 `.svg` 或 `.png` 并嵌入 Markdown。Full 模式在对应图对象中填写 `artifact.tool` 与 `artifact.file`，确定性渲染器会改为嵌入该文件；Lite 模式可直接嵌入。即使使用外部图，报告仍必须保留：

- `FLOW-NN` 业务步骤清单；
- `FLOW-EDGE-NN` 业务流转清单；
- `PARTICIPANT-NN` 时序参与者清单；
- `MESSAGE-NN` 时序消息清单；
- `ROLE-NN` 架构角色职责清单；
- `ARCH-EDGE-NN` 架构关系清单；

这些清单承载稳定编号、职责和 `file:line` 证据，供校验器检查。外部图文件必须位于 repo root 内且真实存在。

## 顺序门禁

报告章节顺序必须是：

1. 机制概述 / 范围；
2. 业务流程图；
3. 时序图；
4. 架构角色图；
5. 全链路和后续分析。

任一图缺失、类型错误、结构不足、职责缺失、证据不可达或顺序错误，报告不合格。
