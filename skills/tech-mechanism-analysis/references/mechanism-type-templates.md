# 机制类型链路模板库（模块 B）

> 配合 `tech-mechanism-analysis` 的 Checklist 第 1/4 步使用。「全链路」对不同形态的机制含义不同——本库给每类机制一套**链路模板**（分段切法 + 每段要讲什么），先识别类型再套模板，避免用一把尺子量所有机制。模板可扩展。

## 用法

1. 按 `scope-and-boundary.md §二` 判 `mechanism_type`。
2. 套对应模板的链路分段，写入 `chain_template`（如 `["produce","flow","process","effect"]`）。
3. `chain_stages[]` 每段一个对象，`segment` 对应模板分段名，逐段填 what/how/why/key_structures/numerical/handoff/evidence。
4. 模板不贴时用 `other` + 自定义分段，在 `mechanism_type_basis` 写明。

## 模板一：data-flow 数据流型

**适用**：有数据被产生 → 存储 → 读取 → 变换 → 作用于输出。关键帧、缓存、渲染管线、音视频处理、序列化。

**链路分段**：`产生 → 流转 → 处理 → 生效`（`produce → flow → process → effect`）

| 段 | 要讲什么 |
|----|----------|
| 产生 produce | 数据怎么被创建 / 写入；数据结构长什么样；写入时机 |
| 流转 flow | 数据怎么被传递 / 查找 / 读取；读的时候假设什么格式 |
| 处理 process | 读取后做了什么变换（插值 / 过滤 / 编解码）——**数值计算常在此段** |
| 生效 effect | 处理结果怎么作用到最终输出（渲染属性 / 写回存储 / 发出） |

> 这是**最通用**的模板，拿不准类型时回退它。用户的「视频编辑器关键帧」正是此型：存储关键帧→播放查找→插值→写入渲染。

## 模板二：lifecycle 生命周期型

**适用**：有 init / configure / run / teardown 的状态推进。资源管理、会话、连接池、组件挂载。

**链路分段**：`初始化 → 配置 → 运行 → 清理`（`init → configure → run → teardown`）

| 段 | 要讲什么 |
|----|----------|
| 初始化 init | 资源 / 状态怎么被创建（默认值、分配） |
| 配置 configure | 怎么被设置参数 / 注入依赖 |
| 运行 run | 运行期行为（循环 / 响应 / 维持）——**时序 / 周期数值常在此段** |
| 清理 teardown | 怎么被释放 / 回收；是否有泄漏隐患 |

## 模板三：call-chain 调用链型

**适用**：一次操作沿入口 → 委派 → 核心 → 副作用传递。请求处理、命令分发、事件处理。

**链路分段**：`入口 → 委派 → 核心 → 副作用`（`entry → dispatch → core → side-effect`）

| 段 | 要讲什么 |
|----|----------|
| 入口 entry | 操作从哪进来（API / 事件 / 命令） |
| 委派 dispatch | 怎么路由 / 分发到具体处理者 |
| 核心 core | 核心处理逻辑——**算法 / 决策数值常在此段** |
| 副作用 side-effect | 产生什么副作用（写库 / 发消息 / 回调） |

## 模板四：state-machine 状态机型

**适用**：有显式状态 + 转移 + 动作。播放器状态、协议状态机、向导流程。

**链路分段**：`状态 → 转移 → 动作`（`state → transition → action`）

| 段 | 要讲什么 |
|----|----------|
| 状态 state | 有哪些状态、用什么表示（枚举 / 字段） |
| 转移 transition | 什么条件触发状态切换；转移规则 |
| 动作 action | 进入 / 转移时执行什么——**条件数值常在此段** |

## 模板零：other

以上都不贴时自定义分段，须在 `mechanism_type_basis` 写明为何自定义、分段依据。不硬塞通用模板导致失真。

## 每段都要做的（无论哪个模板）

- **what / how / why**：做了什么 / 怎么实现 / 为什么这么设计。
- **key_structures**：关键数据结构 / 类 / 函数（非空）。
- **numerical**：该段是否含数值计算（true → 第 5 步必须给工作举例）。
- **handoff**：与下一段的衔接约定（数据格式 / 接口契约 / 时序 / 隐含假设）——跨段衔接缺陷的来源。
- **evidence**：挂 `file:line`，非空。

## 反模式

- 用「调用链型」模板套一个本质是数据流的机制 → 漏掉「数据怎么存」。
- 只讲入口段不讲生效段 → 全链路断了。
- handoff 不写 → 跨段衔接的隐含约定丢失（设计债的高价值区）。
