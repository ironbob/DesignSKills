# 数值操作工作举例（模块 B · 签名能力）

> 配合 `tech-mechanism-analysis` 的 Checklist 第 5 步使用。本 skill 的**重点是技术细节**。凡链路中 `numerical=true` 的环节，讲解时**必须给真实数值的工作举例**：适度规模示例数据 + 逐步实际运算，且**运算逻辑必须与原代码一致**。这是「确实读懂了代码」的硬佐证，不是装饰。非数值段不强制。

## 一、为什么要工作举例

讲数值机制只贴公式 / 念函数名，读者（和未来的你）都无法验证是否真懂、是否和代码一致。一组**真实数值逐步算到底**的例子，既讲清了机制，又**证伪了「貌似懂了其实没懂」**——如果算出来的结果和代码行为对不上，说明理解错了，回去重读。

## 二、四要素（每条 numerical_example 必填）

1. **operation**：运算名（如「ease-in-out 三次缓动插值」「EMA 平滑 α=0.3」）。
2. **sample_data**：具体示例数据——**适度规模，非平凡**：
   - 不太少：能体现操作的行为（含分支 / 边界），不要只有一组平淡数据。
   - 不太多：够说明即可，不堆一长串。
   - 例：插值给 2 个关键帧 + 1 个查询时间点；EMA 给 4-5 个采样点。
3. **computation_steps**：逐步实际运算（每步可核，不跳步），最终给 **result**。
4. **faithfulness_note**：声明运算逻辑与原代码一致（含是否做了代码翻译、保留了哪些影响结果的步骤）。

## 三、忠实于原代码：必要时做代码翻译

工作举例的运算**必须按原代码的真实逻辑走**，不能套一个通用教科书公式。常见情形：

- **原代码是 C++/GLSL/shader/汇编**：直接读公式易错。可对代码做**等价翻译**（如转 Python）**实际运行求值**，把真实结果填进 result。`code_translation` 记录翻译方式 + 译文要点，`faithfulness_note` 声明「译文等价保留原逻辑，已实际运行」。
- **原代码有隐含步骤**（如先 clamp 再插值、用整数定点、有查找表）：逐步运算里要体现这些步骤，不能省。省了会导致结果对不上。
- **原代码有随机性 / 种子**：固定种子或取一个确定分支演示，并在 note 说明。

> 翻译纪律：**忠实保留影响结果的所有步骤**（单位、精度、clamp、溢出回绕等），不得简化掉。翻译只是求值手段，不是改写算法。

## 四、写法示例（关键帧缓动插值）

```
operation: ease-in-out 三次缓动插值（对应 KeyframeTrack.sampleAt）
sample_data: 关键帧 [(t=0.0, v=0), (t=1.0, v=100)]，缓动 ease-in-out cubic；查询 t=0.25
computation_steps:
  1. 归一化进度 u = (0.25-0.0)/(1.0-0.0) = 0.25
  2. ease-in-out cubic 映射（原代码 t'=4u³ 当 u<0.5）：t' = 4×0.25³ = 4×0.015625 = 0.0625
  3. 线性插值 v = 0 + (100-0)×0.0625 = 6.25
result: v = 6.25（在 t=0.25 处，缓动使值远低于线性插值的 25）
code_translation: 将 C++ sampleAt 的缓动分支译为 Python 求值（保留 u<0.5 分支与 4u³ 公式）
faithfulness_note: 运算与原代码 sampleAt 的 ease-in-out cubic 分支逐行对应，已转 Python 实际运行验证结果 = 6.25；未省略归一化与分支判断。
```

## 五、自检（交付前）

- 每个数值段都有 ≥1 条工作举例？（脚本硬卡）
- 示例数据非平凡（不是 1+1、不是单一平淡值）？
- computation_steps 逐步可核、没跳步？
- **result 对得上代码逻辑**？（若翻译运行过，结果来自实际运行）
- faithfulness_note 明确声明一致 + 是否翻译？
- 贴了 `file:line` 指向被举例的代码？

## 六、反模式

- 只贴公式不给数值 → 读者无法验证。
- 示例数据太简（1+1）→ 体现不出操作行为。
- 套通用公式，忽略原代码的 clamp / 定点 / 分支 → 结果对不上代码，失真。
- 翻译时简化掉影响结果的步骤 → 不忠实。
- 编造 result → 违反禁止编造证据。
