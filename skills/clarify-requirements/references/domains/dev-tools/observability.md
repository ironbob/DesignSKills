## 匹配信号
- 关键词：监控 / 指标 / metrics / 日志 / logging / 链路 / tracing / 告警 / APM / 可观测 / OTel。
- 场景：线上排障（从告警→指标→日志→链路逐层下钻定位根因）、容量规划、SLI/SLO 度量与告警。

## 继承要点（速览）
开发者工具通用全适用；本类增量是——**三支柱（Metrics/Logs/Traces）关联 + 采样与高基数治理 + OTel 标准化采集**。可观测的核心命题不是"采集更多"，而是"出问题能从告警一路下钻到根因"。

## 核心价值要素
让系统状态**外部化、可查询、可关联**，回答"现在有没有问题→是哪里→为什么"。不可缺：① 三支柱且能相互跳转（trace_id/log_id 串联）② 高基数指标治理（标签集可控）③ 标准化采集协议（OpenTelemetry）。

## 业界标配功能
- **三支柱**：Metrics（聚合数值/Counter/Gauge/Histogram）、Logs（带结构的离散事件）、Traces（请求跨服务的因果链）——因为单一支柱只能看到"发生了什么"，关联起来才能回答"为什么"。
- **统一关联键**：trace_id / span_id 注入日志与指标，告警→指标→trace→日志逐层下钻——否则三套系统各说各话，排障靠人脑拼。
- **结构化日志**：JSON/字段化 + 采集，避免 grep；配合采样防止成本爆炸。
- **告警即代码**：告警规则/阈值/路由版本化入仓、可 review；P95/P99 分位延迟、错误率、饱和度（USE）/RED 方法做条件。
- **高基数治理**：标签维度可控（user_id 当 metric label 会把时序库打爆）——因为高基数是 TSDB 成本与查询变慢的头号杀手。
- **采集标准化（OpenTelemetry）**：厂商无关的 SDK/Collector，避免被单一后端锁定——这是 OTel 成为 CNCF 第二活跃项目的根本原因。
- **仪表盘与 SLI/SLO**：服务地图（service map）、错误预算（error budget）燃烧速率告警。
- **API/CLI/查询语言**：PromQL/LogQL、HTTP API、CLI 导出——让告警脚本和自动化能消费，不只靠 GUI。

## 业界标杆做法
- **Prometheus + Grafana**：pull 模型 TSDB + 可视化事实标准 — PromQL + 多维标签 + 服务发现，做对了"指标查询表达力与生态开放"。
- **OpenTelemetry**：CNCF 采集标准 — 厂商无关的统一 SDK/Collector（metrics/logs/traces），做对了"一次埋点，后端可换，解耦采集与存储"。
- **Datadog**：商业 APM 一体化 — 三支柱开箱即关联 + 海量集成，做对了"三支柱无缝下钻与最低接入摩擦"。
- **Loki**：Prometheus for logs — 日志只对标签建索引、正文不做全文索引，做对了"用降本换可用，与 Grafana 同栈无缝跳转"。
- **ELK / OpenSearch**：全文检索 + 聚合分析 — 做对了"日志全文检索与复杂聚合"，代价是资源与成本。
- **SkyWalking**：APM + 服务拓扑 + 链路 — 做对了"Java agent 字节码增强零侵入接入 + 中文社区"。

## 常见陷阱与反模式
- 只部署三套工具、不串联 trace_id → 三套系统各说各话，排障靠人脑拼（这是可观测项目最常见的"花钱没效果"）。
- 高基数标签（user_id/订单号当 metric label）→ TSDB 基数爆炸、成本飙升、查询超时。
- 告警靠 UI 手点、不入库 → 告警规则漂移、无法 review、人走规则丢；告警要么不响要么狂响，最终被全员屏蔽。
- 全量 trace 不采样 → 后端存储成本爆炸，反而拖慢查询；正确做法是尾部采样（tail sampling，按错误/延迟保留）。
- 把日志当指标用（count 日志行算错误率）→ 丢失维度与分位精度；反之把高基数业务数据塞指标也是错位。
- 采集端厂商私有 SDK 锁死 → 想换后端要重埋点，OTel 化彻底解决。

## 本节点专属澄清
- 三支柱（Metrics/Logs/Traces）是否**齐且可关联**（统一 trace_id 跳转）？
- 采集是否走 **OpenTelemetry**（避免后端锁定）？
- 告警是否**即代码**、基于 SLI/SLO 与分位延迟，而非手点阈值？
- **高基数治理**策略（哪些字段能做标签、采样比例）怎么定？
- 日志检索要**全文检索（ELK）**还是**降本（Loki）**？容量与成本预算多少？
- 自建还是 SaaS（Datadog）？数据出境/合规是否允许 SaaS？
