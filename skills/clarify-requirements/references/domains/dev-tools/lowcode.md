# 低代码 / 无代码 / 搭建平台 领域知识

> 树路径：dev-tools > lowcode
> 继承：`dev-tools`（可扩展（自定义组件/插件）/ API / CLI（导出/迁移）/ 文档示例均适用）
> 使用前先读父类：[`README.md`](README.md)

## 匹配信号
- 关键词：低代码 / 无代码 / 搭建 / 拖拽 / 可视化建模 / 流程编排 / 表单引擎 / 物料 / 协议。
- 场景：业务人员/低门槛开发者拖拽搭建内部表单+流程+报表应用、围绕某生态（钉钉/微信/企业系统）快速产出应用。

## 继承要点（速览）
开发者工具通用部分适用（可扩展、文档、导出迁移）；本类增量是——**可视化编排 + 物料生态 + 可移植（导出源码/协议）**。低代码的核心张力是"易搭"与"搭到深处撞墙"，一切设计围绕"撞墙时有逃生通道"。

## 核心价值要素
让**非专业开发者也能产出可上线应用**，且专业开发者能在边界外扩展。不可缺：① 可视化编排（页面/流程/数据）② 物料生态（可复用组件/模板）③ 撞墙逃生（导出源码/自定义组件/协议化、可迁出不被锁死）。

## 业界标配功能
- **可视化编排**：拖拽搭页面、表单设计器、流程（BPMN）编排、数据模型建模、规则/公式引擎——因为目标用户写不了代码，可视化是唯一入口。
- **物料 / 组件生态**：内置组件库 + 自定义组件（React/Vue 物料）+ 模板市场——因为内置组件永远不够，能不能接自有组件决定平台能不能"长大"。
- **数据与集成**：连接器连数据库/REST/第三方（钉钉/企业微信/SaaS），避免每个应用重新造数据层。
- **多端发布**：一键发 PC/移动/小程序，响应式与多端适配。
- **权限与流程治理**：角色/部门/数据权限、审批流、表单权限——内部应用几乎都要走流程。
- **可移植 / 导出**：导出源码或基于开放协议（如 LowCodeEngine 的搭建协议），可二次开发、可迁出——因为"搭到一半发现做不了、又被平台锁死"是低代码最大风险。
- **版本与环境**：dev/prod 环境、应用版本与回滚。
- **API / CLI / 协议**：对开发者侧提供物料开发脚手架、应用导入导出、CI 集成。

## 业界标杆做法
- **Retool**：内部工具低代码事实标准 — 直连任意 SQL/REST 数据源 + JS 写逻辑 + 自定义组件，做对了"数据源透明可接 + 不假装不需要代码"。
- **Appsmith**：开源内部工具平台 — 自托管 + 可写 JS + 连接器丰富，做对了"开源可自托管、数据不出企业"。
- **阿里 LowCodeEngine**：开源低代码引擎（alibaba/lowcode-engine）— 协议先行（搭建协议/物料协议）+ 运行时+编排器可拆，做对了"不锁死、协议化、可自建平台"，是宜搭等产品的底座。
- **钉钉宜搭**：阿里商业化低代码 SaaS — 页面/表单/流程/报表拖拽 + 深度绑定钉钉与阿里云协同生态，做对了"低门槛 + 协同办公场景快速落地"。
- **腾讯微搭（WeDa）**：腾讯云低代码 — 主打微信生态（小程序/企业微信）集成，做对了"微信生态一键发布、低门槛出海小程序"。
- **Mendix**：企业级低代码（西门子）— 全生命周期建模+版本治理+企业集成，做对了"复杂企业级应用的低代码承载力"。

## 常见陷阱与反模式
- 没有"撞墙逃生"（不能导出源码/不能自定义组件/封闭协议）→ 搭到深处撞墙即被平台锁死，要么推倒重来要么妥协（低代码头号风险）。
- 物料封闭、无法接自有组件 → 稍有定制需求就做不了，沦为"只能搭简单表单"。
- 可视化逻辑无限堆叠（流程/公式嵌套几十层）→ 比代码更难维护、不可 review、不可 diff，最终变成"图形态屎山"。
- 数据与逻辑和平台强耦合、不能迁出 → 换平台=重写，供应商锁定最痛处。
- 把低代码当成"完全不需要开发者"→ 复杂业务仍需写代码（连接器/自定义组件/逻辑），缺少开发者扩展点会卡死。
- 无 dev/prod 环境与版本回滚 → 搭建改动直冲线上、不可回滚（搭建型应用同样要受发布纪律约束）。

## 本节点专属澄清
- 主要搭建者是谁——**业务人员**（纯无代码）还是要**专业开发者可扩展**（低代码+自定义组件）？
- 是否支持**自定义组件 / 物料开发**（React/Vue），还是物料封闭？
- 应用能否**导出源码 / 基于开放协议迁出**（防供应商锁死）？开源引擎（LowCodeEngine/Appsmith）还是商业 SaaS（宜搭/微搭/Retool）？
- 数据是否要**自托管/不出企业**（影响选开源自托管 vs 商业 SaaS）？
- 围绕哪个**生态**（钉钉/微信小程序/企业现有系统）？连接器是否覆盖？
- 有没有**dev/prod 环境与版本回滚**？可视化逻辑的可维护性边界在哪（避免图形态屎山）？
