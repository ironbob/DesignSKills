## 匹配信号
- 关键词：流水线 / pipeline / CI / CD / 构建 / 发布 / 制品 / GitOps / DevOps 平台 / 触发器。
- 场景：代码推送后自动构建测试打包、发布到 K8s/registry、变更以 Git 为单一事实源滚动部署。

## 继承要点（速览）
开发者工具通用全适用；本类增量是——**流水线即代码（Pipeline as Code）+ 制品可追溯 + 部署可回滚**。CI（构建测试）与 CD（部署交付）正在解耦，GitOps 把 CD 从"推送"转向"声明式同步"。

## 核心价值要素
让"**提交即交付**"可重复、可审计、可回滚。不可缺：① 流水线即代码，与仓库同生命周期 ② 制品（镜像/包）唯一标识与可追溯（commit→构建→制品→部署）③ 部署原子化、失败可回滚。

## 业界标配功能
- **流水线即代码**：YAML/Groovy 与仓库同版本人审，避免"只在某人浏览器里配的流水线"——因为那样无法 review、无法灾备、换人就丢。
- **触发器矩阵**：push / PR / 定时（cron）/ Webhook / 手动 / 上游制品变更；支持路径过滤、并发与互斥（同一分支串行避免互相覆盖产物）。
- **可复用单元**：Reusable Workflow / 模板 / 共享步骤 / 内置 Marketplace/Plugin——因为重复粘贴 200 行 YAML 到每个仓库是流水线腐烂的头号原因。
- **机密与凭据管理**：secrets/变量分环境、最小权限、脱敏日志；破坏性操作要环境保护（prod 需人工审批 / 必经 review）。
- **矩阵与缓存**：matrix 多 OS/版本并行（如同时跑 ubuntu/macos × node18/20）；依赖缓存把冷启动从分钟级压到秒级。
- **制品管理**：build→推 OCI 镜像/artifact→签名（Sigstore/cosign）→部署，全程可追溯——因为"哪个 commit 上了 prod"是合规与排障刚需。
- **可观测与自助调试**：步骤日志可重试单步、可 SSH 进 runner 调试、明确失败原因；失败不告警等于没流水线。
- **幂等与回滚**：部署支持 dry-run、蓝绿/金丝雀、一键回滚到上一版制品。

## 业界标杆做法
- **GitHub Actions**：SaaS 流水线事实标准 — YAML 即代码 + Marketplace 复用生态 + matrix/缓存开箱即用，零配置上手门槛最低。
- **GitLab CI**：与代码托管一体化的内置流水线 — `.gitlab-ci.yml` 同仓、自带制品库/Registry/SAST，单体平台减少工具拼装。
- **Jenkins**：可编程流水线（Jenkinsfile/Groovy）+ 海量插件 — 做对了"可编程、可承载任意复杂老系统"，代价是插件治理与运维负担。
- **ArgoCD**：GitOps 声明式 CD — 以 Git 为唯一事实源、controller 持续把集群状态向声明收敛，做对了"部署可审计、可漂移检测、可一键回滚"。
- **CircleCI**： orbs（可复用配置包）+ 远程 Docker runner — 做对了"配置复用标准化 + 矩阵并行加速"。
- **Drone**：容器原生 CI，每步一个容器 — 做对了"隔离与可移植"，pipeline 与容器镜像绑定。

## 常见陷阱与反模式
- 流水线在 UI 里点出来、不入库 → 无法 review、无法灾备、换人就丢（"只在某人浏览器里"是流水线腐烂头号病因）。
- 一个超大 mono 流水线跑全量（30+ 分钟，无缓存/无矩阵）→ 反馈慢，开发者为省时间手动绕过 → 质量门形同虚设。
- CI 与 CD 耦合在一条流水线里（构建完直接推 prod）→ 部署不可独立验证、不可回滚、事故半径大。
- prod 凭据长期挂在 CI 变量且无审批 → 一次误触发/泄露即事故（须环境保护 + 人工审批）。
- 制品与 commit 无强绑定（用 `latest` 跑 prod）→ "线上跑的是哪个版本"答不出，排障与回滚都无从下手。
- 破坏性步骤无 dry-run / 无回滚 → 把"自动发布"做成了"自动出事"。

## 本节点专属澄清
- 流水线是**即代码**（YAML 入库 review）还是 UI 配置？
- CI 与 CD 是否**解耦**（CI 出制品、CD 由 GitOps 同步）？
- **制品如何标识与追溯**（commit→镜像→部署），prod 是否禁止 `latest`？
- prod 部署有无**环境保护 / 人工审批 / 回滚**？
- 触发策略与**并发控制**（同分支串行、避免产物互相覆盖）怎么定？
- 要不要**可复用单元**（模板/Marketplace/orbs）减少跨仓重复？
