## 匹配信号
- 关键词：地图 / 导航 / 路线 / 打车 / 网约车 / 外卖 / 到店 / 探店 / 点评 / 酒店 / 机票 / 火车票 / 景点 / 攻略 / 配送。
- 场景：查路线导航去某地、打车、点外卖等送达、出去玩订酒店机票、找附近好吃的店。

## 继承要点（速览）
C 端低摩擦与核心路径全适用；出行本地生活的增量是——**LBS（位置服务）+ 履约（配送 / 司机 / 库存）+ 双边市场**，重线下、重实时。

## 核心价值要素
让用户**到想去的地方、买到附近的服务、出行有人接单有人送**。不可缺：① **位置服务**（地图 / 定位 / 路线，一切的基础）② **实时撮合与履约**（司机 / 骑手 / 房 / 票的库存与接单，断了就是"叫不到 / 没房间"）③ **可信赖的评价**（线下决策高度依赖他人评价）。

## 业界标配功能
- **地图 / 定位 / 导航**（驾车 / 步行 / 公交 / 骑行，实时路况）。
- **搜索 / 附近**（搜地点 / 店铺 / 服务，按距离排序）。
- **下单 + 撮合**（打车派单、外卖配送、订房订票锁库存）。
- **实时状态**（司机位置 / 预计到达、骑手位置 / 预计送达、订单状态）。
- **价格 / 计价**（一口价 / 计时计程 / 动态加价、费用明细）。
- **支付 + 评价**（在线支付、到店核销、对司机 / 骑手 / 店铺打分点评）。
- 收藏地点 / 路线规划 / 行程。
- 客服 / 纠纷处理（错单、迟到、退款、安全问题——O2O 高频投诉区）。

## 业界标杆做法
- **高德地图 / 百度地图**：精准定位 + 多模式导航 + 实时路况 + 打车聚合，把"去哪儿、怎么去"做成基础设施。
- **美团 / 大众点评**：到店餐饮 + 外卖 + 酒旅 + 点评体系，"吃住玩"全场景 + 强评价信任。
- **滴滴 / Uber**：网约车实时派单 + 动态定价 + 行程安全（行程分享 / 一键报警），双边市场撮合标杆。
- **携程 / 去哪儿**：机票 / 酒店 / 火车票 / 景点票务 + 行程，把出行预订做成全链路。
- **饿了么 / 美团外卖**：餐厅 + 骑手 + 实时配送轨迹 + 预计送达，履约可视化是留存关键。
- **飞猪**：阿里系出行 / 本地生活平台，会员与优惠打通。

## 常见陷阱与反模式
- 定位 / 导航不准 → 核心功能失效，出行场景一次错就弃用（地图类头号死因）。
- **撮合失败 / 无库存**（叫不到车、订不到房、没人接单）→ 体验断裂、用户流失到竞品（双边市场冷启动最大难关）。
- 履约状态不透明（不知道骑手 / 司机到哪、几点到）→ 焦虑 + 客服压力集中。
- 价格不透明 / 动态加价没说清 → 信任崩塌、投诉与差评。
- 评价注水 / 虚假 → 线下决策依据失效，平台信任根基被掏空。
- 冷启动一边缺人（没司机 / 没商家 / 没用户）→ 飞轮转不起来。

## 本节点专属澄清
- 偏**地图导航**、**出行打车**、**外卖配送**、**到店 / 点评**还是**酒旅票务**？子品类履约链路差异巨大。
- 是**自营履约**（自有骑手 / 司机）还是**平台撮合**（聚合第三方）？
- 双边市场冷启动怎么解决（先拉司机 / 商家还是先拉用户）？
- **实时状态**（位置 / 预计到达 / 库存）要做到什么颗粒度？
- 评价体系怎么保证真实性（防刷评 / 防虚假）？
- 涉及**线下安全**（行程分享、紧急联系、保险）怎么兜底？
- 价格机制（一口价 / 计时计程 / 动态加价）口径是什么？
