# 健康 / 运动 / 健身 领域知识

> 树路径：c-end > health-fitness
> 继承：`c-end`（低摩擦 / 留存 / 激励仍适用）
> 使用前先读父类：[`README.md`](README.md)

## 匹配信号
- 关键词：运动 / 跑步 / 步数 / 健身 / 训练 / 打卡 / 心率 / 睡眠 / 体重 / 卡路里 / 饮食 / 薄荷 / 计划 / 课程 / 数据同步 / 手环 / 体脂。
- 场景：出门跑步记录轨迹、跟着课程练一组、每天称体重记卡路里、看昨晚睡眠得分。

## 继承要点（速览）
C 端低摩擦与留存全适用；健康运动的增量是——**数据采集（自动 / 硬件）+ 计划性训练 + 正反馈闭环**，且运动反人性，留存几乎全靠激励。

## 核心价值要素
帮用户**动起来并坚持下去、看清自己的身体变化**。不可缺：① **数据记录**（自动采集 > 手动录入，否则坚持不下来）② **计划 / 课程引导**（不知道练什么就放弃）③ **正反馈**（成就 / 进步 / 社交，对抗惰性）。

## 业界标配功能
- **数据记录**：步数 / 距离 / 轨迹 / 配速 / 心率 / 卡路里（自动采集优先）。
- **训练 / 课程**：跟练视频、分部位 / 分目标的训练计划、难度分级。
- **体征追踪**：体重 / 体脂 / 睡眠 / 心率 / 女性周期，趋势图。
- **饮食 / 热量**：食物录入 / 卡路里计算 / 营养素（健身减脂强需求）。
- **目标 + 计划 + 提醒**：设目标、每日计划、定时提醒运动。
- **激励**：打卡 / 连续天数 / 成就徽章 / 排行榜 / 挑战赛。
- **硬件 / 第三方同步**：手环 / 手表 / 体脂秤、Apple Health / Google Fit / 华为运动健康数据互通。
- 社区 / 动态 / 关注。

## 业界标杆做法
- **Keep**：跟练课程 + 训练计划 + 社区 + 智能硬件，把"练什么、怎么练、坚持练"做成闭环。
- **薄荷健康**：食物库 + 卡路里 + 饮食记录，把"吃进多少热量"量化到食物级。
- **Apple Health（健康）/ 华为运动健康**：系统级数据中枢，聚合手环 / 手表 / 体脂秤多源健康数据。
- **Strava**：跑步 / 骑行轨迹 + 路段（Segment）排名 + 强社区，把运动做成社交竞技。
- **Fitbit / 小米运动健康**：手环硬件 + App，靠自动采集降低录入摩擦、靠数据可视化留住用户。
- **Nike Training Club（NTC）**：专业训练课程 + 计划，品牌内容驱动的标杆。

## 常见陷阱与反模式
- 依赖**手动录入** → 摩擦大，用户坚持不下来（运动类最大流失原因，自动采集是解药）。
- 有数据无**计划 / 引导** → 用户不知道练什么、怎么练，看几天新鲜就流失。
- **正反馈不足** → 运动反人性，没有成就 / 进步 / 社交激励，留存断崖。
- 数据不准 / 同步失败 → 信任受损，"白练了"的挫败感直接劝退。
- 训练无难度分级 → 新手劝退 / 老手无聊，覆盖不到目标人群。
- 把健康数据当**纯粹展示**，不驱动行动 → 数据墙没人看，留存空转。

## 本节点专属澄清
- 偏**运动训练**、**体征 / 健康数据**还是**饮食 / 热量**？子品类数据模型差异大。
- 数据主要靠**自动采集（硬件 / 传感器）**还是**手动录入**？接哪些设备 / 平台？
- 是否提供**训练计划 / 课程**？是跟练视频还是自定义计划？
- **留存靠什么**激励（打卡 / 连续 / 排行榜 / 社区 / 挑战赛）？
- 涉及**健康 / 医疗**数据，隐私与合规（数据存储、是否构成医疗器械边界）要求如何？
- 目标人群是减脂 / 增肌 / 普通健身 / 慢病管理哪类？决定内容与指标。
