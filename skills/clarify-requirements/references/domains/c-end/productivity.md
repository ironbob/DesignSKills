# 效率 / 笔记 / 待办 / 日历 领域知识

> 知识复核：2026-07
> 树路径：c-end > productivity
> 继承：`c-end`、`c-end/tools`（低摩擦 / 用完即走 / 召之即来仍适用）
> 使用前先读父类：[`README.md`](README.md)（C 端）、[`tools.md`](tools.md)（工具类）

## 匹配信号
- 关键词：笔记 / 文档 / 待办 / 任务 / 清单 / 日历 / 日程 / 提醒 / 收藏 / 稍后读 / 知识管理 / 看板 / 番茄钟 / 协作 / 模板 / 标签 / 收件箱。
- 场景：开会随手记要点、早上列今天要做的任务、收藏文章稍后读、整理自己的知识库。

## 继承要点（速览）
C 端低摩擦、工具类"召之即来 / 用完即走"全适用；效率类的增量是——**快速捕获（capture）+ 组织结构化 + 跨端同步 + 复盘检索**，从"记一笔"升级到"管一库"。

## 核心价值要素
帮用户**快速记下来、有序找得到、随时随地能用到**。不可缺：① **极速捕获**（想法 / 任务转瞬即逝，录入多一步就流失）② **结构化组织**（笔记本 / 标签 / 看板 / 日程，否则记了找不到）③ **跨端同步与检索**（数据在哪都能用，否则工具成孤岛）。

## 业界标配功能
- **极速捕获**：全局快捷键 / 小组件 / 通知中心 / 语音 / 微信收藏转发，一键记一笔。
- **笔记 / 文档**：富文本 / Markdown / 块（block）编辑、图片 / 附件 / 表格、双向链接 / 反向链接。
- **待办 / 任务**：清单 / 任务、优先级、截止日期、子任务、**看板**（看板流 Trello 式）、番茄钟。
- **日历 / 日程**：日程、提醒、重复、多日历、与任务联动。
- **组织结构**：笔记本 / 文件夹 / 标签 / 收藏 / 稍后读收件箱、**搜索**（全文检索是知识库命脉）。
- **跨端同步**：多设备 + 云同步 + 离线 + 协作分享。
- **模板 / 数据库 / 视图**（Notion 式 table / board / calendar 视图，知识管理进阶）。

## 业界标杆做法
- **Notion**：block + 多视图数据库 + 模板 + 双向链接，把"笔记 / 任务 / 知识库 / 协作"合成一个万能积木，灵活度标杆。
- **滴答清单（TickTick） / Todoist**：极速录入 + 自然语言识别日期 + 清单 / 看板 / 日历一体，把待办做到快与全的标杆。
- **印象笔记（Evernote） / OneNote**：网页剪藏 + 多端同步 + 全文检索，老牌知识库与稍后读。
- **Things**：设计克制 + GTD（收件箱 / 今天 / 计划 / 某天）流程清晰，把"优雅 + 方法论"做成体验标杆。
- **飞书文档 / 腾讯文档 / 石墨**：在线协作文档 + 多人实时编辑 + 评论 / 任务，把"个人效率 + 团队协作"打通。
- **Obsidian / Logseq**：本地 Markdown + 双向链接 + 图谱，把"个人知识管理（PKM）"做成可长期持有的知识网络。

## 常见陷阱与反模式
- 录入入口埋得深 / 要点好几下 → 想法转瞬即逝，捕获失败（效率类头号死因，必须一键）。
- 组织结构混乱 / **没有好搜索** → 记了找不到，工具沦为"信息黑洞"，用户放弃。
- 无**跨端同步** → 换设备用不了，数据孤岛，活跃断崖。
- 功能臃肿（什么都塞） → 失去"快"，违背效率工具核心，被更专的工具替代。
- 协作功能缺失（需要分享时） → 个人工具撑不住团队场景，流失到协作平台。
- 模板 / 视图死板 → 复杂场景组织不了，深度用户流失。

## 本节点专属澄清
- 偏**笔记 / 文档**、**待办 / 任务**、**日历 / 日程**还是**综合知识库**？核心动作不同。
- **极速捕获**入口要做到多快（快捷键 / 小组件 / 语音 / 转发）？
- 组织靠**笔记本 / 文件夹**、**标签**、**看板**还是**双向链接 / 数据库**？
- **跨端同步与离线**要不要支持，覆盖哪些端？
- 全文**检索**能力多强（能否搜到附件 / 历史版本）？
- 是**纯个人**还是要**协作分享**（决定是否需要多人编辑 / 权限）？
- 变现模型（免费 + 订阅 / 买断）？订阅限制会不会卡住核心同步功能？
