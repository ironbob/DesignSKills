## 匹配信号
- 关键词：审批流 / 请假报销 / 工作流引擎 / OA / 协同办公 / 流程节点 / 表单设计器 / 文档协作 / 知识库。
- 场景：企业要把请假/报销/采购/用印等各类申请电子化流转，并沉淀制度文档、会议纪要、项目资料。

## 继承要点（速览）
B 端通用全适用；OA 的增量是——**可配置的审批流引擎（含会签/或签/条件分支/退回）+ 文档协作的权限与版本治理**，目标是把"找领导签字"和"找文件"从线下搬线上、可追溯。

## 核心价值要素
让组织的**审批决策**有据可依、可追溯，让**协同知识**可沉淀、可复用、可管控。不可缺：① 灵活可配的审批流引擎（不写代码改流程）② 文档/知识的权限与版本控制。

## 业界标配功能
- 审批流引擎：节点类型（发起/审批/会签/或签/抄送/条件分支）、退回/加签/转交/委托代理、节假日与岗位感知（按"岗位"而非"具体人"流转，换人不改流程）。
- 表单设计器：拖拽生成申请表，字段联动、必填规则、数据校验、关联主数据（如关联组织架构/项目）。
- 流程类型模板：请假/报销/采购/用印/合同/出差等预置模板，后台可配不找开发。
- 移动审批：钉钉/企微/飞书/小程序内审批，待办聚合与消息提醒。
- 文档协作与知识库：在线编辑（多人协同）、版本历史、评论 @、目录树与权限（读/评/编辑/管理）。
- 待办与通知中心：跨系统的待办聚合、即将超期提醒、已读未读、撤回与重提。
- 审计与合规：审批留痕（谁同意/拒绝/退回、何时）、文档操作日志、电子签/用印留痕、数据权限（部门/项目可见性）。
- 报表：审批效率（平均时长/超时率/瓶颈节点）、知识库活跃度。

## 业界标杆做法
- **钉钉 / 企业微信 / 飞书**：IM+协同一体化平台 —— 把"审批/待办/文档/通讯录/SSO"做成平台底座 + 开放 API，定义了"消息即入口、审批推到聊天"的移动办公标准。
- **泛微（e-cology）**：大中型 OA 平台标杆 —— 以"自定义表单 + 流程引擎 + 二次开发工具"应对复杂组织架构与会签/条件分支，验证了"流程可配"是企业级 OA 的分水岭。
- **蓝凌**：以"知识管理 + 智能 BPM 流程"见长 —— 主打知识密集型/流程驱动型企业，把"制度文档-知识图谱-BPM"串成一条线，解决"审批完文档就散落"的问题。
- **致远互联**：标准化协同管理 —— 以"标准化产品 + 中小企业快速上线"降低 OA 落地门槛，证明"开箱即用模板"比"纯定制"更易被采纳。
- **Confluence / Notion**：文档协作/知识库双标杆 —— Confluence 以"页面树+空间权限+@通知"成为研发/制度文档事实标准；Notion 以"块(block)+数据库视图"让知识可结构化查询，验证了"文档+轻数据库"比纯网盘更可治理。

## 常见陷阱与反模式
- 审批流按"具体人"配而非"岗位" → 人员一变动流程就断，运维灾难（OA 头号维护成本来源）。
- 流程节点过多/会签滥用 → 一个单据卡 8 个节点，流转缓慢，用户绕过系统走线下（OA 被架空）。
- 表单字段过多 → 填写成本高，员工拖延或填错（义务劳动反噬采纳率）。
- 通知风暴 → 每一步都推送，用户屏蔽消息，反而漏审（提醒泛滥等于没有提醒）。
- 文档无版本/无权限治理 → 同名多版本满天飞、谁都能改、删除无留痕，知识库变垃圾场。
- 审批完不留痕或留痕不可查 → 合规审计与责任追溯失败，事后扯皮。

## 本节点专属澄清
- 要管哪几类**审批**（请假/报销/采购/用印/合同/项目）？各自流程差异大吗？
- **审批引擎**要支持到什么程度（会签/或签/条件分支/退回/委托/按岗位流转）？是否要后台可配不写代码？
- 流转是按"**岗位**"还是"**具体人**"？组织架构数据从哪来（HR 系统同步）？
- 是否需要**移动端**审批？要集成钉钉/企微/飞书 还是独立 App？
- **文档/知识库**需求范围（在线协同编辑/版本/权限/全文检索/知识图谱）？
- 与现有系统集成（SSO/通讯录/HR/ERP-报销转凭证/电子签）？
- 合规要求：审批与文档**留痕**是否要满足内控/审计/等保？电子签合规？
