## 匹配信号
- 关键词：报表 / 看板 Dashboard / 数据可视化 / 数据大屏 / 指标体系 / 自助分析 / 多维分析 OLAP / 钻取。
- 场景：业务/管理层要看经营数据、销售/库存/财务报表，要做可交互的看板或数据大屏辅助决策。

## 继承要点（速览）
B 端通用全适用；BI 的增量是——**指标口径统一（数仓/语义层）+ 行列级数据权限 + 自助分析**。核心矛盾不在"画图好看"，而在"同一指标所有人看到同一数 + 该看的人才能看"。

## 核心价值要素
让业务能**自助**从数据中得到一致、可信、及时的决策依据。不可缺：① 统一指标口径（语义层/数仓建模，杜绝"两张报表对不上")② 数据权限（行级/列级，谁看哪部分）。

## 业界标配功能
- 数据接入层：多数据源（MySQL/PG/Oracle/数仓/Excel/API/埋点），定时与实时抽取（ETL/ELT）。
- 数据准备与建模：清洗、关联、构建语义层/数据集，统一指标定义（口径、计算口径、单位）。
- 报表与可视化：表格、折线/柱/饼/漏斗/地图/桑基图、数据大屏、条件格式/预警。
- 自助分析：拖拽维度度量、上卷下钻、切片器、联动、自定义计算字段、即席查询。
- 权限体系：数据源/数据集/看板级权限 + 行级（只看本区域）+ 列级（隐藏薪酬列）+ 分享与水印。
- 调度与分发：定时刷新数据、定时邮件/钉钉企微推送报表、订阅与预警（指标超阈值告警）。
- 审计与治理：看板访问日志、指标变更留痕、数据血缘（字段从哪张表来）、数据质量监控。

## 业界标杆做法
- **Tableau**：可视化标杆 —— 以"VizQL + 拖拽生成 + 智能推荐图表"把"探索式分析"做到极致，验证了"让业务自助分析"比"IT 提数"更能释放数据价值。
- **Power BI（微软）**：企业级 BI 集成标杆 —— 以"语义层 + DAX + 与 Excel/Azure/Teams 深度集成 + 行级安全(RLS)"占领企业办公入口，证明 BI 的胜负在"与数据源和办公流的衔接"而非仅画图。
- **帆软（FineBI / FineReport）**：国产 BI 市场份额第一 —— FineReport 以"复杂中国式报表 + 填报"起家、FineBI 以"自助分析 + 数据大屏"补齐，验证了"报表+自助 BI+大屏"三位一体最贴合中国企业"既要规范报表又要探索分析"的双重诉求。
- **观远数据（Smartbi 思迈特 / 观远 BI）**：国产智能 BI —— 以"一站式敏捷分析 + AI+BI（智能洞察/归因）+ SaaS 云原生"降低分析门槛，定义了"云原生 + 智能化"的国产 BI 方向。
- **Metabase / Apache Superset**：开源 BI 双标杆 —— Metabase 以"零 SQL 易用"降低中小企业入门门槛；Superset 以" SQL Lab + 丰富图表 + 大规模并发"覆盖有数据团队的企业，验证了"开源可二开"在成本与自主可控上的价值。
- **Quick BI（阿里云）**：云原生 BI —— 以"与阿里云 MaxCompute/DataWorks 深度集成 + 数据同步与权限管控"在云上数据栈里做到低摩擦，证明 BI 与数据底座的同源集成能省掉大量搬运。

## 常见陷阱与反模式
- 只重"图表好看"不重"指标口径统一" → 同一个 GMV 财务和运营报表对不上，互相打架（BI 失信的头号原因）。
- 没有行级/列级权限 → 任何人能看全公司/看敏感薪酬列，数据泄露（B 端合规硬伤）。
- 一切报表靠 IT 提数 → 排队几周出一张表，业务等不起，回退到 Excel 自建"野生报表"（口径更乱）。
- 数据源脏却直接展示 → ETL 没清洗、空值/重复未处理，看板数字跳变，决策被误导。
- 看板只建不管 → 报表越堆越多，没人维护、口径过时，沦为"数据垃圾场"。
- 缺数据血缘与质量监控 → 上游表一改，下游看板悄悄算错却无人知晓。

## 本节点专属澄清
- 目标用户：**管理层看大屏** / **业务自助分析** / **IT 定时报表**，谁是主力？（决定是重可视化、重自助、还是重填报）
- 数据**来源**有哪些（业务库 / 数仓 / Excel / 第三方 API）？是否已有数仓/数据集市？
- **指标口径**如何统一？有无指标字典/语义层？关键指标（如 GMV/活跃/毛利）谁定义？
- 数据**权限**要求（行级看本区域 / 列级隐藏敏感字段 / 看板级可见性）？是否需水印防截图？
- 是否要**数据大屏 / 定时推送 / 预警订阅**？
- 实时性要求（T+1 批处理 还是 准实时）？并发与数据量级？
- 部署与合规：私有化/信创？数据敏感等级？是否需数据血缘与访问审计？
