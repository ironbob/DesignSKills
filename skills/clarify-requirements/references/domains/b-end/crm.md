# 客户 / 销售管理 领域知识

> 树路径：b-end > crm
> 继承：`b-end`（角色矩阵 / 状态机 / 集成 / 合规 / SLA 均适用，特别是"销售漏斗状态机"与"数据权限/字段级安全"）
> 使用前先读父类：[`README.md`](README.md)

## 匹配信号
- 关键词：客户管理 / 商机 / 销售漏斗 / 线索 / 客户公海 / 跟进记录 / 合同管理 / 销售预测。
- 场景：销售团队需要管理从"线索→商机→成单→回款"的全流程，并要分团队/分区域隔离客户数据。

## 继承要点（速览）
B 端通用全适用；CRM 的增量是——**漏斗状态机驱动销售过程 + 数据归属/公海规则 + 客户主数据**（往往是市场/销售/服务多系统的唯一事实源）。

## 核心价值要素
让"**线索→商机→成交→回款→复购**"全链路有迹可循、可预测、可复制。不可缺：① 统一客户主数据（去重、合并、唯一标识）② 漏斗/阶段状态机（商机推进的可视化与预测）。

## 业界标配功能
- 客户/联系人/商机主数据：去重、合并、字段级权限（手机号/身份证可按角色隐藏）——防止撞单与数据泄露。
- 线索分配与公海：线索按规则（区域/行业/轮询）自动分配，超期未跟进自动回收公海——保证线索不被囤积。
- 漏斗与销售阶段管理：商机分阶段（如 10%验证→50%方案→80%商务→100%赢单），每阶段有退出标准。
- 跟进记录与提醒：拜访/电话/邮件留痕，下次跟进任务提醒（钉钉/企微/邮件）。
- 报价/合同/回款：报价单模板、合同电子签（集成 e签宝/上上签）、回款计划与应收跟踪。
- 销售预测与报表：基于漏斗转化率 + 加权预测（阶段概率 × 金额）给出预测。
- 权限与团队协作：数据按"我/我的团队/我的部门/全部"隔离；大客户团队共享但外人不可见。
- 审计日志与数据导出留痕（合规与防止飞单）。

## 业界标杆做法
- **Salesforce**：CRM 标杆 —— 把"对象（客户/商机/联系人）+ 字段 + 视图 + 工作流 + 权限"做成 PaaS（AppExchange 生态），二次开发不侵入核心。
- **纷享销客**：国产"连接型 CRM" —— 用"1+N 连接方案"打通上下游（经销商/渠道协同），解决传统 CRM 只管内部销售、管不到渠道的盲区。
- **销售易（Neocrm）**：AI 原生 CRM —— 以 NeoAgent 把销售跟进记录自动结构化、自动生成下次动作建议，降低一线填写负担。
- **HubSpot**：营销-销售-服务一体化 —— 用"接触点时间线 + 自动化工作流"让市场线索自动培育、达到分数线才转给销售，定义了"营销自动化(MAP)+CRM"的标准衔接。
- **Zoho CRM**：性价比一体化 —— 以"画布设计器(可定制详情页布局)+ 全模块(大中小微)"压低企业落地成本，验证了"字段/布局/流程可配置"比"功能多"更能降低 TCO。

## 常见陷阱与反模式
- 只管"录入客户"不管"漏斗推进" → 销售用 Excel 也行，CRM 沦为通讯录（采纳率塌方的头号原因）。
- 撞单 / 重复客户 → 没有去重与客户唯一标识，两个销售抢同一客户、互相覆盖，信任崩塌。
- 公海规则缺失或过死 → 要么线索被囤积不流转，要么刚联系就回收，销售抵触录入。
- 字段太多 + 强制必填 → 销售嫌麻烦不录或录假数据（销售录入是 CRM 数据质量的命门）。
- 数据权限不分层 → 销售互相看底价/提成，或离职带走客户名单（B 端数据安全硬伤）。
- 只看"签单额"不看"回款/毛利" → 漏斗看着漂亮但现金回不来，无法反映真实经营。

## 本节点专属澄清
- 客户**主数据**唯一标识是什么（统一社会信用代码 / 手机号）？多渠道来源如何去重合并？
- **销售漏斗**分几个阶段？每阶段的"推进条件"是什么？是否有阶段概率/加权预测？
- **线索分配与公海**规则（手动 / 自动路由 / 多久未跟进回收）？
- 数据**权限层级**（我 / 团队 / 部门 / 全部）？哪些字段要字段级加密隐藏？
- 要对接哪些系统（营销自动化 MAP / 电子签 / ERP-合同回款 / 企微钉钉 / BI）？
- 销售预测口径（漏斗加权 / 历史季节性 / 人工提报）？考核的是签单额还是回款/毛利？
- 有无**渠道/经销商**协同需求（决定要不要"连接型"而非纯内部 CRM）？
